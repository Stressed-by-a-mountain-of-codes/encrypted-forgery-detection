# Dataset 04: IMD2020 — Modern Realistic Tampering Dataset

**Full Name:** IMD2020: A Large-Scale Dataset for Image Manipulation Detection  
**Authors:** Wang, Tan, Zhou, et al. (Tsinghua, etc.)  
**Year:** 2020 (ACM MM 2020)  
**Website:** https://github.com/Imd2020/IMD2020  

---

## My First-Person Walkthrough

I went through this dataset because it's **designed for realistic tampering** — not the obvious copy-paste of CASIA, but **semantically meaningful manipulations** that people actually do: object removal, person removal, background replacement, expression editing. 2,000 images with **pixel-level masks** for 4 manipulation types.

When I looked at the composition: **1,000 authentic** (from Flickr, diverse scenes), **1,000 manipulated** — 250 each of **Splicing, Copy-Move, Removal, Inpainting**. The key difference: manipulations are **semantically coherent** — "remove this person", "replace background with similar scene", "change facial expression". Done with **professional tools (Photoshop) + manual refinement**, not algorithmic. Masks are **pixel-perfect**.

The authentic images are **high-res (up to 4K)**, downsampled to 1024×1024 max. Manipulations preserve **lighting, perspective, shadows** — much harder to detect than CASIA. This is **what real forensics faces**.

On the 2nd iteration, I checked usage: **TruFor (Paper 8)** uses IMD2020 as a main benchmark. **DL Survey (Paper 9)** cites it as "modern realistic dataset". For encrypted-domain: **IMD2020 images are JPEG** (from Flickr/web), so they have native compression. Good for testing encrypted methods on **real-world compression + realistic manipulation**. But **only 1,000 forged** — small for training, good for testing.

**My takeaway:** IMD2020 = **realistic, semantic, modern**. Use as **held-out test set** alongside COVERAGE. The 4 manipulation types map to different forensic challenges: Removal/Inpainting test **generative artifact detection**, Splicing tests **boundary inconsistency**, Copy-Move tests **self-consistency**. For encrypted domain: test if your method catches **semantic manipulation artifacts** that survive encryption (noise, residuals).

## Manipulation Type Breakdown (250 each)

| Type | Description | Forensic Challenge |
|------|-------------|-------------------|
| **Splicing** | Object/scene from another image pasted in | Boundary inconsistency, lighting mismatch |
| **Copy-Move** | Object duplicated within image (translated) | Self-similarity, repeated noise pattern |
| **Removal** | Object removed + background inpainted | Generative artifacts, texture synthesis traces |
| **Inpainting** | Region filled (expression edit, object add) | GAN/diffusion artifacts, semantic consistency |

## Standard Evaluation (Per IMD2020 Paper / TruFor)

| Metric | Splicing | Copy-Move | Removal | Inpainting | Overall |
|--------|----------|-----------|---------|------------|---------|
| **mIoU (TruFor)** | ~0.72 | ~0.68 | ~0.58 | ~0.55 | ~0.63 |
| **Pixel F1** | ~0.80 | ~0.76 | ~0.68 | ~0.65 | ~0.72 |
| **AUC-ROC** | ~0.93 | ~0.91 | ~0.87 | ~0.85 | ~0.89 |

> **Note:** Harder than CASIA, easier than COVERAGE. Realistic middle ground.

| **Compare with COVERAGE results** | Both modern — do they correlate? |

## Constraints & Gotchas

- ❌ **Only 1,000 forged** — small, not for training
- ❌ **No official split** — create fixed test set
- ❌ **Native JPEG QFs vary** — uncontrolled compression
- ❌ **Semantic manipulations** — may not match your threat model
- ✅ **Most realistic manipulations** — Photoshop + manual
- ✅ **4 distinct types** — fine-grained forensic analysis
- ✅ **Used by TruFor (SOTA)** — direct comparison
- ✅ **Native compression** — matches real encrypted-domain input

## Relevance to My Project

- Tests encrypted detection on **semantically meaningful edits**

- Native JPEG = **real input distribution**
